# Reuse the 541 retrieval output

Run `541_Faiss.ipynb` from Day54. Part A runs locally. Part B needs the configured Google Cloud project and writes `output/541_faiss/semantic/` after successful embedding calls. The semantic bundle is generated by execution; it is not a precomputed dataset shipped with this notebook.

## Files

| File | Purpose |
| --- | --- |
| `products.faiss` | Exact inner-product index over normalized document vectors |
| `products.json` | Ordered product metadata and the exact text embedded for each product |
| `manifest.json` | Embedding model, location, dimensions, task types, metric, row IDs, count, and shared catalogue SHA-256 |
| `product_vectors.npy` | Normalized document vectors; useful for inspecting or rebuilding the index |
| `example_query.npy` | Normalized vector for the saved example question |
| `example_query.json` | Original example question |
| `example_context.txt` | Retrieved product documents for that question, labeled with product IDs |
| `example_retrieval.json` | Question and retrieved product IDs with similarity scores |

The row at position `i` in the FAISS index belongs to `products.json[i]`. Do not sort or replace metadata independently. Rebuild the bundle if product text, ordering, embedding model, or dimensions change. Keep the numeric bundle separate; its vectors cannot be searched with text embeddings.

## Next notebook: retrieval, then generation

1. Load and validate the bundle using section 17 of `541_Faiss.ipynb`. This works in a new kernel after the imports in section 1.
2. Create the Google client with the embedding location stored in the manifest. Use its embedding model, dimensions, and `RETRIEVAL_QUERY` task to embed the new question.
3. Convert the query to a `(1, dimensions)` float32 array and normalize it with `faiss.normalize_L2`.
4. Search the loaded index. Apply exact product filters when required, then use row positions to retrieve the product documents.
5. Join the documents into context labeled with product IDs. If no records satisfy the filters, report that rather than generating a product recommendation.
6. Pass the question and context to the configured Gemini generation model. Ask it to use only the supplied records, cite IDs such as `[P006]`, and say when the records lack an answer.

The embedding model and generation model serve different purposes. Generation may use `MODEL_ID` from `course_config.py`; retrieval must continue using the embedding settings stored in the bundle. Changing the generation model does not require re-embedding products.

To demonstrate the generation step without a new embedding call, use the saved example question and `example_context.txt`. That context only answers the saved question; retrieve again for a different question. Similarity scores are rankings, not probabilities or proof that a record satisfies every request.
